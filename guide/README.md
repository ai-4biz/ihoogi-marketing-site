# iHoogi — מדריך מיקוד מטרה וקהל

## התהליך המעודכן לפי הנחיות רונה

1. לפני השיחה: עד שלושה קישורים ציבוריים לאתר/רשתות, לא חובה. אין דרישה לפרטי קשר.
2. הדרכה לבעל העסק בלבד: קטגוריה ותת־תחום → הבנת ההצעה בפועל → מטרת בעל העסק → קהל → צורך → חידוד התאמה → בדיקת המיקוד עם בעל העסק → סיכום אישי.
3. אין שאלון ללקוחות, כללי דירוג, הדגמת פניות, קמפיין או ערוצי שיווק בתוך ההדרכה.
4. אחרי הסיכום: שם, נייד ומייל לצורך בקשת סיכום מסודר.
5. בחירה נפרדת, לא מסומנת מראש, בניסיון לינק חכם ממותג עם 50 פניות מדורגות ללא עלות.
6. למעוניינים: לוגו PNG/JPEG/WebP עד 1MB. הבקשה מוצגת עם יעד אספקה בתוך שני ימי עסקים.
7. הסכמה לשמירת הפרטים ולמימוש הבקשה נפרדת מהסכמה לדיוור שיווקי.

המידע הציבורי הוא רקע לא מאומת; תשובות בעל העסק קובעות את המטרה והמיקוד.

## מה נשמר ומה עדיין חסר

הקישורים, קטעי המקור, השיחה והסיכום נשמרים בשרת, ולבקשת סיכום מתווספים פרטי הקשר,
הבחירה בניסיון והלוגו. סטטוס המימוש הוא pending_manual.
עדיין אין שליחת מייל, יצירת לקוח/שאלון, סנכרון פרופיל או ליד לחשבון office@ihoogi.com.
הממשק מציג במפורש שהבקשה נשמרה בבדיקות וששליחה עדיין אינה פעילה.
אין הודעות ללקוחות, כתיבות לחשבונות לקוחות או שינויים באתר הראשי/Production.
backend/schema.sql הוחל רק ב־Staging; index.ts/common.mjs/intake.mjs הם מקור הפונקציה החיה.
יכולת גישה אקראית לשיחה (256 ביט), hash בלבד ב־DB; RLS, ללא גישה ציבורית ישירה לטבלאות.

## הרצה

Node.js 24 ומעלה. cp .env.example .env והגדירו סודות שרת; אין להוסיף .env לגיט.
node --env-file=.env server.mjs
npm test

בדיקות: תקציב, כשל, מקביליות, URL ציבורי, קריאת מקור, שמירת הקשר,
פרטי קשר והסכמה, בחירת ניסיון, לוגו, ואחר שמאפשר תשובה חופשית בלי קריאת AI מוקדמת.
בדיקת ממשק מלאה בדפדפן לא הושלמה.
